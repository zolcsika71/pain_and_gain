# ADR 0003: Evaluate replay-informed strategy proposals

Status: Proposed. The original combat-positioning change was implemented and live-validated separately. A narrow, one-tick engagement-boundary retention candidate is implemented locally; a new build-identified match exercised ordinary approach and hold behavior but not range-six retention. The user accepted that residual live-evidence gap for a checkpoint, without claiming a strategic benefit. The other proposals remain unimplemented.

## Proposed evaluation order

1. **Healer support positioning.** Damaged `pg_player1_melee_1` is four or more tiles from every functioning healer at older-replay ticks 47–52 and newer-replay ticks 113–114, outside ranged-heal distance three. Test whether a bounded healer support objective increases in-range healing opportunities and friendly survival without unacceptable flag loss. Observe action logs or other direct action evidence and compare multiple active matches; health changes alone are insufficient.
2. **Stable local combat targets — narrow candidate in progress.** Newer-replay `pg_player1_ranged_5` moves between (49,48), (50,47), and (49,48) at ticks 113–115 while enemy range crosses the five-tile cutoff. The local candidate keeps the previous living target for one tick at range six only when no enemy is within five; range seven, a second outside tick, target loss, or weapon loss releases it. Normal nearest-target selection inside five tiles remains unchanged. This can remove one approach/flag/approach decision cycle in a same-target range-5 → 6 → 5 scenario, but the old capture is no longer available for full re-evaluation, congestion may explain the observed step, and issued commands were not logged. Compare actual range-three access, target switches, CPU cost, and outcomes in new code-provenance matches before claiming a benefit.
3. **Post-capture flag allocation.** At tick 100 both replays still select an already owned first flag while other flags are neutral or enemy-owned. Evaluate allocating selected units to another flag against the current first-flag fallback. Measure net score, flag retention, combat survival, and outcomes; additional captured flags impose army-wide penalties, so more captures are not inherently better.

## Consequences

These are evidence-backed hypotheses, not established strategic improvements. Their order reflects the immediate observed loss of heal access, then possible movement switching, then a scoring tradeoff. Only the narrow boundary-grace candidate has been implemented locally. Replay `6ab995f16fdfd118847097eb` identifies its build and shows ordinary approach/hold behavior without available-console errors, but never exercises range-six retention. The user's checkpoint acceptance is a waiver of that branch-specific live gate, not evidence that the branch ran or improved outcomes. The completed older replay review and prior combat-movement live check do not validate this new build.
