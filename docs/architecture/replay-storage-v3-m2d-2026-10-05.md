## Implemented boundary

`analyzeFixtureScoreReplay` in `tools/replay-score-analysis-fixture.js` accepts
only an explicit canonical marked temporary root, schema 1/2, one replay,
1–64 distinct score fingerprints and full/compact mode. It opens read-only,
loads one coherent score-selection snapshot and closes the owner after analysis.
The existing synchronous API/CLI remains SQLite-free; score validation,
grouping, mapping and report assembly have one shared implementation.

The exclusive `withReadSnapshot({scoreSelection:{replayId,fingerprints}}, cb)`
mode resolves both optional collection flags and current/retired identities
under the existing lock/transaction. Missing selections retain unknown findings;
pending, retiring, active-intent or unavailable current evidence rejects. Output
ownership checks use indexes; optional score maps are metadata only. Existing
log snapshot defaults remain unchanged.

Pinned raw responses retain exact bytes and semantic malformed/unsupported
findings. Admitted property roots are hash-verified and capped at 1 MiB before
allocation, decoded as complete strict UTF-8 JSON, bounded to 1,024 nesting
levels, and counted toward the 8 MiB expanded-metadata cap. Raw responses have
4 MiB/source and 16 MiB/selection limits. Every-close and explicit primary-error
flags preserve thrown null; none of this qualifies arbitrary OS close failures.

## Limits retained

This slice can qualify only fixed-selection corpus independence and bounded
synthetic score-only integration. It cannot qualify general analyzer expansion,
combined log/score input, lifecycle/cache integration, general bounded-v2 access,
C2, M3 migration/rehearsal, M4 cutover, production performance, power-loss
durability or additional platforms. Earlier M2b/M2c failures and the unresolved
intermittent SQLite busy delay remain historical facts; subsets cannot be combined
into a fictitious full-suite pass. Independent review remains a separate task.
